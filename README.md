# Лабораторная работа 7: Запросы на отрезках

## Сборка и запуск

### Команды Makefile:

1. make - собрать все программы
2. make run - запустить тестирование
3. make clean - очистить собранные файлы


## Пункт 1: RSQ (Дерево Фенвика vs Дерево отрезков)

### Результаты тестирования

| Повторение | Дерево Фенвика (с) | Дерево отрезков (с) |
|------------|--------------------|----------------------|
| 1 | 0.0424 | 0.2394 |
| 2 | 0.0422 | 0.2229 |
| 3 | 0.0361 | 0.2076 |
| 4 | 0.0381 | 0.3022 |
| 5 | 0.0350 | 0.2127 |
| **Среднее** | **0.0388** | **0.2369** |

**Дерево Фенвика** показало лучшие результаты, обогнав дерево отрезков **в 6 раз**.

### Почему Фенвик быстрее?

1. **Минимальная константа** - используется всего 2-3 битовые операции на итерацию
2. **Отсутствие рекурсии** - простой цикл вместо рекурсивных вызовов
3. **Экономия памяти** - массив из n элементов
4. **Лучшая локальность** - последовательный доступ к памяти


## Пункт 2: RMQ (Sparse Table V1 vs V2)

### Результаты тестирования

| Повторение | V1 (n × logN) (с) | V2 (logN × n) (с) |
|------------|-------------------|-------------------|
| 1 | 0.0276 | 0.0162 |
| 2 | 0.0274 | 0.0167 |
| 3 | 0.0274 | 0.0163 |
| 4 | 0.0275 | 0.0167 |
| 5 | 0.0281 | 0.0200 |
| **Среднее** | **0.0276** | **0.0172** |

**V2 (logN × n)** работает лучше, обгоняя V1 **в 1.5 раза**.

### Причины:

1. **Локальность данных** - при запросе оба обращения к памяти идут в пределах одной строки
2. **Использование кэша**
3. **Меньше TLB-промахов** - обращение к одной странице памяти вместо двух
